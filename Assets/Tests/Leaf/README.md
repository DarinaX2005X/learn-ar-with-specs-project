# Curtain integration checks

Status: authored; offline compilation against actual LEAF 2.0 source, generated installed SIK source and Lens SDK declarations passes with TypeScript 5.9.3 in the SDK's non-strict mode. Strict mode reports eight errors within third-party LEAF source and none in these test files. Full Lens Studio compile and Preview runs remain unverified.

`LeafIndex.ts` registers `countercase-curtain-revision`, `countercase-curtain-reach` and `countercase-curtain-cancel`, with a 60-second scenario timeout.
Attach that script to one enabled root object through Lens Studio MCP. Do not attach an automatic scenario client to the shipping scene. The integration owner installs the Asset Library `Leaf` package with its compatible SIK and Bitmoji dependencies, verifies plugin `com.snap.leaf.LeafPlugin`, opens the LEAF panel and lists scenarios before execution. Run scenarios serially; every panel run resets the Lens.

The runtime must expose a read-only `global.countercaseLeaf.read()` snapshot matching `CountercaseLeafProbe.ts`. `frameObservedRoles` comes from the displayed recording model registry, not the proof result. These tests never assign runtime state or call the compiler. SIK Interactables are named `CurtainHandle`, `CloseCurtain`, `RewindAlarm`, `ComparePrevious`; source confirms the first three and the integration owner has accepted the comparison contract. `RewindAlarm` selects the alarm tick and pauses. `CurtainHandle` tap selects the opposite endpoint; `CloseCurtain` is idempotent. The initial scene has a closed curtain. `ComparePrevious` toggles displayed recording and proof between retained and current sealed tapes; authoritative `revision` and `aperture` stay current while `frameRevision` identifies the selected tape.

The revision scenario exercises two suspects → open curtain → changed public recording at the same tick → one suspect → reverse action → original evidence and suspects. Closing an already closed curtain checks the no-op guard. The IK scenario separately checks handle and close-control reach; an IK timeout or unintended indirect routing is a reachability finding and must not be hidden by substituting a scripted interactor.

After a failure or timeout, retain the scenario-manager RUNS/PASSED/FAILED log lines and the exact failing assertion. A panel UI success message alone is insufficient. Do not call a run passed without the scenario-manager result.

Compatibility pin: official Specs sample [LEAF package](https://github.com/specs-devs/samples/blob/110a145b6572a17fa94d86f18b76047278014729/AI%20Music%20Gen/Packages/Leaf.lspkg), SHA256 `c877d77b8af24b079c4d1d9384afe3dc45e80d321d1a71f680379e5cc73a8fea`. This LEAF 2.0 package declares SpectaclesInteractionKit 2.0.0 and Studio 5.22. Do not install the latest LEAF 4.0 into this project: it imports InteractionKit 4.0. The compatible package has no `eventTimeoutMs` property; use the scenario timeout. Do not patch third-party package imports. The IK factory creates a scripted fallback by default; the reach scenario sets diagnostic policy to `fail-fast` and rejects indirect routing.

The cancellation scenario starts a real LEAF/SIK selection and drag, waits for uncommitted movement, then makes its test interactor unavailable. SIK's InteractionManager dispatches `TriggerCanceled` for an inactive selected interactor; the test never invokes the application's handlers. It asserts revision, evidence and proof remain committed and checks input recovery. This simulates input availability loss; physical tracking remains untested. Read-only `grab` and `draftAperture` telemetry must be mounted.

The revision scenario also toggles to the retained recording after opening, checks original frame identity, observed/rendered roles and proof, then returns to the new recording without changing authoritative revision or aperture. This covers retention at the alarm tick; full archival playback is not covered.

Scope limits: pixel readability, stereo and rear leakage require focused visual Preview inspection. Repeated released input state is checked through `stopSelecting()` twice; this does not inject duplicate SIK release events. No performance or physical-device comfort claim follows from a Preview pass.
