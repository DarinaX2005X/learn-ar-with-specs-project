# TableKit development tools

To inspect the six TableKit states, select the `CountercaseRuntime` component in Inspector, enable `developerStateGallery`, then restart Preview. Disable it and save/reopen or restart Preview to return to a new ordinary game; the inspection mode does not preserve an active case.

From the repository root, run:

```sh
python Tools/TableKit/test_tablekit.py
```

Requires Python 3.10+, NumPy, Node.js and npm. If needed, install the validation
dependency with `python -m pip install numpy==1.26.4`.
The runner obtains **TypeScript 5.9.3** through npm's cache, compiles the four
TableKit modules with strict checking into a temporary OS directory, validates
all 18 models and exactly 13 WAVs (three legacy clips plus ten museum mechanism clips), then runs adapter tests. The temporary output
is removed on exit. No project assets are regenerated by this command.

Asset validation fails when models or audio are missing, unexpected, empty,
malformed, inconsistent with the manifest, or have invalid indices/normals/audio
levels. It includes the affected filename in geometry and audio error messages.

`generate_tablekit.py` regenerates the original GLBs and manifest. Its optional
`--review-dir OUTPUT_DIRECTORY` produces an offline contact sheet only when
requested; it has no dependency on a review directory. That optional render also
requires Pillow. `generate_role_silhouettes.py` requires Shapely and derives the
public head outlines from original head geometry.

`python Tools/TableKit/generate_museum.py` regenerates the connected MuseumBuilding
and appends its measured contract to the manifest. It batches static room detail
by material, embeds the four original Collection JPEGs, and preserves semantic
anchor names. The asset suite checks five open doorway rays, a closed masonry
ray, UV counts, embedded JPEG headers and linear colour factors.

`python Tools/TableKit/generate_partitions.py` regenerates the two reversible
exhibition screens. Long and short variants are exactly 2.4×2×0.15 m and
1.25×2×0.15 m, centred on X/Z with ground Y=0. The asset suite verifies those
authoritative bounds, including every botanical leaf and inlay.

To regenerate audio, set `CLAD_SFX_ENGINE` to an installed official CLAD
`build-sfx/tools` directory, then run `node Tools/TableKit/generate_sfx.cjs`.
The engine is an external development dependency; no machine-specific path is
stored in this repository.


The audio validator has a fixed 13-name allow-list independent of metadata.
`verify_tablekit_audio.py` retains original legacy limits and stereo cloth, while
museum clips require mono, 45 to 500 ms, peak below .30, DC below .002 and faded
endpoints. The original legacy limits remain peak below .5, DC below .01 and
last-100-sample peak below .025. Both groups also match frozen approved bytes,
channel layouts and frame counts in Assets/Audio/TableKit/tablekit-audio-contract.json.
Run `python Tools/TableKit/test_audio_validation.py` for focused positive/negative
checks. Numeric limits are not a native listening approval.

`generate_sfx.cjs` owns only the original cloth/engage/latch clips.
`generate_museum_sfx.cjs` is the original separate ten-clip synthesis tool, using
CLAD_SFX_ENGINE in the same way. To experiment, pass an explicit temporary output
directory: `node Tools/TableKit/generate_museum_sfx.cjs TEMP_OUTPUT_DIRECTORY`.
It uses stochastic synthesis; regenerated bytes are not promised to reproduce the
frozen recording. Do not regenerate or update the frozen contract just to pass
validation. New audio requires its own listening review and approved byte/hash
update. This validator/check suite never runs either generator or changes WAVs.
